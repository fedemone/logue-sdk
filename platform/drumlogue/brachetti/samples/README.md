# Reference samples

This directory is the reference-recording input for the measure-first workflow:
`modal_extract.py` derives modal ratios and per-mode T60s from a recording, and
`refcmp.py` scores a render against one.  It is **not** build output and nothing
here is generated.

## These files are tracked despite `.gitignore` — read this before adding more

`platform/drumlogue/brachetti/.gitignore` carries a bare `*.wav`.  Its own
comment says what it was for — *"Rendered WAV output (generated by
render_presets tool)"* — but the pattern is unanchored, so it matches at every
depth, including this directory, and the reference recordings were never
committed.  They were restored in Sept 2026 by **force-adding** them
(`git add -f`), which is why they are here now.

**The consequence for anyone adding a new reference: `git add -A` will silently
skip it.**  Git only ignores *untracked* files, so the 67 files already here
behave normally — edits and deletions are picked up — but a new `.wav` needs an
explicit `git add -f samples/whatever.wav`, or it will look added and never be.
If that trips anyone up, the clean fix is a negation in `.gitignore`
(`!samples/*.wav`); the rendered output this rule actually targets already lives
in `rendered*/` directories, which are ignored separately.

## What the absence cost, while it lasted

Worth keeping, because both failures were caused by the missing files rather
than by anything in the DSP:

- **Pass 45 tuned the gong against prose and got it backwards.**  With no
  recording to measure, it took its spectral target from two *written*
  references in this repo that contradict each other, picked one, and shipped
  an `hfTilt` that moved the preset onto the wrong instrument.  Pass 46
  measured `Chinese-Gong.wav` — 196 Hz power centroid, 0.0 % of its energy
  above 3 kHz — and reverted it.  The contradiction is now explained: the two
  notes describe the two *different* gongs in this directory.
- **`refcmp.py` was broken for four passes and nobody could see it.**  The
  pass-41 GtrStr removal shifted every preset index above 25 down by one and
  left the tool pointing Ride at 32 (RidBel), RidBel at 33 (Bongo) and HHat-O
  at 27 (Conga).  It could not run at all without references, so the breakage
  was invisible.  It now locates renders by NAME, not index.

## The two gongs are different instruments

This directory holds both recordings the `k_Gong` enum names, and they are not
the same thing.  Measured:

| | power centroid | >3 kHz | T60 | dominant partials |
|---|---|---|---|---|
| `Chinese-Gong.wav` | 196 Hz | **0.0 %** | 1.28 s | **91.5** (68.8 % of all energy), 328, 658, 739, 342, 674, 725, 1375 |
| `Gong-long-G#.wav` | 2473 Hz | **38 %** | 3.2 s+ | 324, **1604** (as loud as the fundamental), 269, 1711, 286, 1652, 1139 |

`refcmp.py` scores against `Chinese-Gong.wav`, and the enum lists it first, so
that is the one the preset is currently voiced to.  The enum's parenthetical —
*"starts with 800 Hz and settles to 1680 Hz"* — describes `Gong-long-G#.wav`,
not it.  **Which of the two the preset should be is an open decision.**

### Known discrepancies — do not "fix" silently

- **HHat-O.**  The enum attributes `TightClosedHat.wav` to preset 26 (HHat-O),
  but `refcmp.py` and `sample_map_classics.json` both pair HHat-O with
  `OpenHatBig.wav` and `TightClosedHat.wav` with HHat-C.  A *closed*-hat
  recording at 11.6 kHz as the reference for the *open* hat looks like the enum
  line is the wrong one, but HHat-O is flagged "HW-approved, do not break", so
  settle it by listening before re-tuning anything against either.
- **Gong.**  Resolved in pass 46 — the "contradiction" was two different
  instruments, both present here.  The open part is which one the preset should
  be; see "The two gongs are different instruments" above.
- **Provenance is not recorded anywhere.**  No source or licence is documented
  for any of these files, and they are now committed to a public repository.
  Worth capturing here — if any of them are not clearly redistributable, that
  is a question about the repo, not just about the tuning workflow.

## Using them

```bash
# modal ratios + per-mode T60s from a recording
python3 modal_extract.py samples/Chinese-Gong.wav
python3 modal_extract.py samples/Taiko-Hit.wav --nmodes 10

# score renders against the references (renders located by NAME, not index)
g++ -std=c++17 -O2 -I. -I.. -I../../common -I../common -DRUNTIME_COMMON_H_ \
    render_presets.cpp -o /tmp/render_presets
/tmp/render_presets /tmp/rc/
python3 refcmp.py /tmp/rc            # defaults to /tmp/rc if omitted
```
